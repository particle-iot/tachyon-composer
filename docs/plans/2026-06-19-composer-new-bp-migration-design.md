# tachyon-composer migration to the new BP — design

Date: 2026-06-19  Status: implemented (pending NA/desktop matrix)

## Goal

Make tachyon-composer produce the **new-BP factory image** (QCM6490, Quectel bp-fw r108 / 2.0.0,
**UEFI boot chain**). Reuse composer's existing rootfs/efi/overlay front-end; replace the
"boot + partitioning" back-end with the one already validated on hardware in tachyon-eugene
(`ptool` + `partition_ext` + `QCM6490_bootbinaries` + `dtb_a` + `core_nhlos`).

## Strategy: replace the back-end (drop the legacy U-Boot path)

- **Keep**: the composer rootfs.ext4 build (24.04 base + tachyon-overlay-tool), versions.json /
  Makefile / Docker machinery.
- **Replace**: the boot chain + partition table → eugene's `ptool.py` + `partition_ext.xml` +
  `QCM6490_bootbinaries` + `dtb_a` + `core_nhlos`.
- **Delete**: the `xbl.elf` U-Boot patch, `qtestsign` signing, `.dtbo`→`/boot/overlays`, and the
  "edit `rawprogram*.xml` size/filename in place" path.

The legacy BP booted via U-Boot; the new BP is UEFI direct boot (`uefi_a` comes from the
bootbinaries), with extra partitions `dtb_a` / `core_nhlos_a`, and the partition table is
generated by ptool — so this is a back-end rewrite, not a small patch.

## Component sourcing (finalized)

| Component (partition) | Source | Method |
|---|---|---|
| **system** (rootfs.ext4) | built by composer (24.04 base + overlay) | reuse |
| **efi** (efi.img) | vendored GRUB from eugene (`BOOTAA64.EFI` + `grub.cfg`) | vendor + build |
| **dtb_a** (dtb.img) | extract **`qcm6490-tachyon.dtb`** from the kernel deb (not `combined-dtb.dtb`!) → FAT16 `make-dtb-img.sh` | extract + pack |
| **core_nhlos_a** (nonhlos-<region>.img) | vendored per-region firmware blobs (em/na) from eugene + `make-nonhlos_img.sh` | vendor + build |
| **bootbinaries / QCM6490_fw** | S3 permanent release `https://tachyon-ci.particle.io/release/tachyon-bp-fw-2.0.0.zip` | fetch |
| **kernel deb** | S3 permanent release `https://linux-dist.particle.io/kernel/release/stable-6.8.0-1058.59particle2/` | fetch |
| **assembly** (ptool/partition_ext/provision/cdt.bin) | vendored from eugene | vendor |

> Key clarification: the filename `combined-dtb.dtb` inside the `dtb_a` partition is only the
> fixed name EDK2/UEFI reads from that partition; the contents must be the Tachyon board's
> `qcm6490-tachyon.dtb`. The kernel Makefile's `combined-dtb.dtb` (a concatenation of multiple
> reference-board `*-ovl.dtb`) is unrelated to Tachyon and must not be used.

## New compose flow

```
1) rootfs.ext4   ← composer: 24.04 base + overlay-tool (stack installs the kernel, etc.)
2) efi.img       ← vendored GRUB (make-efi-img.sh)
3) overlay       ← run-overlay.sh -f rootfs.ext4 (installs kernel + Particle pkgs, applies pins)
4) dtb.img       ← extract qcm6490-tachyon.dtb from the kernel deb → FAT16 make-dtb-img.sh
5) nonhlos.img   ← vendored blobs (make-nonhlos_img.sh --variant em|na)
6) assemble      ← ptool + partition_ext.xml → rawprogram*/patch*, zipped into an EDL-flashable zip
```

## Kernel / base version decision

The rootfs kernel is baked into the 24.04 base by livecd-rootfs (it installs the latest
`linux-particle` from `packages.particle.io/ubuntu noble-stable` at base-build time, no pin).
Both `image-21-4d6898e` and `image-22-938ac1d` ship the **1056** line (confirmed by the build
log: `Unpacking linux-particle (…particle2) over (…1056.57+particle6)`).

To get a fully-particle2 image, `check-pinned-packages` runs
`apt install linux-particle=6.8.0-1058.59+particle2`. Since `linux-image-6.8.0-1058-particle` is
a different package name from the base's 1056 kernel, apt **adds the whole 1058 kernel as a fresh
install alongside** the 1056 one — installing particle2 on a 1056 base works (there is no
cross-ABI problem). `dtb_a` is the particle2 `qcm6490-tachyon.dtb`, so the pinned kernel and dtb
are both particle2. `versions.json`:

- `sources["particle-iot/tachyon-ubuntu-24.04"].param = "22-938ac1d"` (newer base commit than the
  original image-21; both are 1056 — the choice does not depend on the kernel line)
- `env.PKG_linux_particle = "6.8.0-1058.59+particle2"`

Two practical gotchas (see `HANDOFF.md` §2 for detail and evidence):
- **Disk space**: the dual kernel (1056 base + 1058 pinned) plus deps overflow the rootfs;
  headroom was raised from +3GB to +6GB (the `system` partition is 10GB).
- **qemu (x86 hosts only)**: the overlay's `mpv`→`python3-mutagen` postinst segfaults under
  Ubuntu's qemu 8.2.2; use qemu 10.2.3. The real-arm64 CI runner is unaffected.

Consequence: the rootfs carries **both** the 1056 (base) and 1058 (pinned) kernels; `dtb_a` is
1058, so boot must select the 1058 kernel — consider removing the unused 1056 kernel in the
overlay stack.

## Verification (Stage 1)

- Single region first (em ≈ RoW), reusing composer's rootfs.
- Build the factory zip locally → `tachyon.sh edl` + `particle flash --tachyon ...` → into console.
- Then expand to the NA/RoW × headless/desktop matrix.

## TODO / risks

1. **rootfs boot adaptation**: composer's rootfs was designed for U-Boot boot; whether it boots
   cleanly under UEFI/new-BP needs hardware testing and may require kernel cmdline / fstab /
   mount-point changes.
2. **NA/RoW × variant matrix** and region mapping (RoW→em / NA→na) — follow-up.
3. **base rebuild option (Plan B)**: if a different kernel line is ever needed, the base repo
   (`particle-iot/tachyon-ubuntu-24.04`) auto-builds and releases `image-N` on any push to main
   (CircleCI), picking up the latest noble-stable kernel; there is no cron, so it only rebuilds
   when something is pushed.
